# تنظیمات

همه‌ی تنظیمات متغیر محیطی هستن. موقع توسعه توی `.env.local` بذارشون؛ روی سرور از `.env.production` (برای PM2) یا `.env` (برای داکر کامپوز) استفاده کن. متغیرهای واقعی محیط از این فایل‌ها قوی‌ترن. قالب کامل و توضیح‌دار اینجاست: [`.env.example`](../../.env.example).

این فایل‌ها رو هیچ‌وقت کامیت نکن. `.gitignore` همه‌ی فایل‌هایی که با `.env` شروع میشن رو کنار گذاشته، به‌جز `.env.example`.

## برنامه

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `PORT` | `3000` | پورتی که برنامه گوش میده. |
| `HOST` | `0.0.0.0` | آدرس bind. اگه پراکسی روی همون ماشینه، `127.0.0.1` بذار. |
| `MONGODB_URI` | `mongodb://127.0.0.1:27017/sedaamon` | آدرس اتصال MongoDB. **توی production الزامیه.** |
| `SITE_URL` | `http://localhost:3000` | آدرس عمومی سایت؛ برای لینک‌های canonical، sitemap، تصویر اشتراک‌گذاری و `llms.txt`. حتماً آدرس واقعی رو بذار. موقع build خونده میشه (پایین‌تر ببین). |
| `SITE_CONTACT_EMAIL` | خالی | توی صفحه‌های «درباره» و «حریم خصوصی» و داده‌ی ساخت‌یافته نشون داده میشه. موقع build. |
| `ENAMAD_ID`، `ENAMAD_CODE` | خالی | نماد اعتماد الکترونیکی توی فوتر (دامنه‌های ایرانی). هر دو لازمن. موقع build. |
| `APPLE_TEAM_ID` | خالی | Universal Links برای برنامه‌ی مک رو روشن می‌کنه ([desktop/README.md](../../desktop/README.md)). |
| `DEV_ALLOWED_ORIGINS` | خالی | فقط توسعه. میزبان‌های اضافه‌ای که اجازه دارن سرور توسعه رو باز کنن، مثلاً گوشی روی وای‌فای (`192.168.1.20`). |

**تنظیمات زمان build.** مقدار `SITE_URL`، `SITE_CONTACT_EMAIL` و `ENAMAD_*` داخل صفحه‌های ساخته‌شده میره. بعد از تغییرشون دوباره `npm run build` بزن (یا `docker compose up -d --build`).

## پنل مدیریت

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `ADMIN_PHONES` | خالی | شماره‌هایی که میتونن `/admin` رو باز کنن، با کاما جدا (`09123456789,09121111111`). **خالی یعنی پنل مدیریت خاموشه.** |

هر کسی که بتونه روی این شماره‌ها پیامک بگیره، مدیر سایته؛ پس فقط شماره‌هایی رو بذار که سیم‌کارتشون دست خودته.

## پیامک ورود

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `SMS_PROVIDER` | `console` | `console` یا `kavenegar`. |
| `KAVENEGAR_API_KEY` | | برای `kavenegar` الزامیه. |
| `KAVENEGAR_TEMPLATE` | | اسم قالب verify/lookup کاوه‌نگار که متنش فقط یه `%token` داره. |

با `console` کد توی لاگ سرور چاپ میشه. خارج از production کد به صفحه‌ی ورود هم برمی‌گرده تا بدون پیامک تست کنی؛ **توی production فقط توی لاگ میاد**، یعنی هیچ‌کس از راه دور نمی‌تونه وارد بشه. برای کاربرهای واقعی `kavenegar` بذار.

کدها ۵ رقمی هستن، ۲ دقیقه اعتبار دارن، بعد از ۶۰ ثانیه دوباره قابل ارسالن و ۵ بار اشتباه زدن مجازه. نشست‌ها ۳۰ روز می‌مونن.

برای سرویس پیامک دیگه، توی [`src/server/sms.ts`](../../src/server/sms.ts) (تابع `sendOtp`) یه شاخه‌ی جدید اضافه کن.

## LiveKit (صدا و تصویر)

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `LIVEKIT_API_KEY` | `devkey` | باید برابر یکی از کلیدهای `keys:` توی `livekit.yaml` باشه. |
| `LIVEKIT_API_SECRET` | | باید برابر رمز همون کلید باشه. توی production حداقل ۳۲ کاراکتر. |
| `LIVEKIT_URL` | `http://127.0.0.1:7880` | آدرسی که **سرور** با اون به API لایوکیت میرسه. توی داکر کامپوز خودکار تنظیم میشه. |
| `LIVEKIT_PUBLIC_URL` | خالی | آدرسی که **مرورگرها** با اون به لایوکیت میرسن. توی production باید `wss://rtc.example.com` باشه. موقع توسعه خالی بذار تا از آدرس همون صفحه استفاده بشه. |

اگه کلید `devkey` باشه، رمز شامل `devsecret` باشه یا کمتر از ۳۲ کاراکتر باشه، برنامه توی production **اصلاً بالا نمیاد**. کلید واقعی رو با `openssl rand -hex 24` بساز.

تنظیمات خود لایوکیت توی `livekit.yaml` هست (کپی [`deploy/livekit.example.yaml`](../../deploy/livekit.example.yaml)). این فایل رمز داره و توی گیت نادیده گرفته میشه.

## ذخیره‌ی فایل

آپلودها (عکس، فایل، پیام صوتی) تا وقتی `S3_ENDPOINT` رو نذاری روی دیسک همین ماشین میرن.

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `UPLOAD_DIR` | `uploads` | پوشه‌ی ذخیره‌ی محلی. توی داکر `/data/uploads` هست (یه ولوم). |
| `S3_ENDPOINT` | خالی | برای استفاده از فضای S3 سازگار (MinIO، آروان، پارس‌پک، AWS و...) پرش کن. |
| `S3_BUCKET` | | اسم باکت. با `S3_ENDPOINT` الزامیه. |
| `S3_ACCESS_KEY_ID`، `S3_SECRET_ACCESS_KEY` | | کلیدها. با `S3_ENDPOINT` الزامیه. |
| `S3_REGION` | `us-east-1` | |
| `S3_FORCE_PATH_STYLE` | `true` | آدرس‌دهی path-style (`endpoint/bucket/key`) که بیشتر سرویس‌های غیر AWS لازم دارن. |
| `MOVIE_MAX_MB` | `4096` | بیشترین حجم فیلم برای کتابخونه‌ی سینما، به مگابایت (حداکثر ۵۱۲۰). فیلم اول توی `UPLOAD_DIR/.incoming` نوشته میشه و بعد به محل ذخیره میره، پس حتی با S3 هم همین‌قدر جای خالی روی دیسک لازمه. |
| `MOVIE_IMPORT_ALLOW_PRIVATE` | خاموش | اگه `true` باشه، «دانلود از لینک» از آدرس‌های داخلی و محلی (شبکه‌ی داخلی، `localhost`) هم دانلود می‌کنه. پیش‌فرض خاموشه تا کسی نتونه سرور رو به سمت چیزهایی بفرسته که فقط خود سرور بهشون دسترسی داره. |

باکت می‌تونه (و بهتره) خصوصی بمونه: فایل‌ها از طریق خود برنامه سرو میشن و دسترسی هر کانال چک میشه. محدودیت‌ها: ۵ مگابایت برای هر فایل و ۱۰ فایل برای هر پیام. فایلی که آپلود شده ولی به پیامی وصل نشده بعد از ۲۴ ساعت پاک میشه.

همه‌ی کانال‌های سینما از یه کتابخونه‌ی فیلم مشترک برای کل برنامه پخش می‌کنن (MP4 یا WebM؛ MP4 با H.264 و AAC توی همه‌ی مرورگرها پخش میشه). فقط مدیر کل سایت (`ADMIN_PHONES`) از تب **فیلم‌ها** توی `/admin` مدیریتش می‌کنه: یا فایل رو آپلود می‌کنه، یا لینک مستقیم یه فایل MP4/WebM رو می‌ده تا سرور خودش توی پس‌زمینه دانلودش کنه (هم‌زمان حداکثر سه تا؛ با ری‌استارت سرور دانلودهای نیمه‌کاره از بین می‌رن). مدت فیلم دانلودشده رو سرور از خود فایل می‌خونه و به ffmpeg نیازی نیست. زیرنویس‌های متنی داخل فیلم (سافت‌ساب: SRT، ASS/SSA، WebVTT و زیرنویس متنی MP4) هم همین‌طور از فایل خونده و توی پخش‌کننده نشون داده میشن و فارسی از اول روشنه؛ زیرنویس‌های تصویری (PGS و VobSub) پشتیبانی نمیشن. فایل زیرنویس جدا (SRT، VTT یا ASS/SSA؛ با UTF-8، UTF-16 یا windows-1256) رو هم از دکمه‌ی زیرنویس‌های هر فیلم توی همین تب میشه اضافه کرد. بقیه از داخل هر سینمایی کتابخونه رو می‌بینن و تماشا می‌کنن. پراکسی جلوی برنامه باید اجازه‌ی این آپلودها رو بده: [`deploy/nginx.conf`](../../deploy/nginx.conf) محدودیت حجم رو فقط برای `/api/movies` بالا برده؛ Caddy به‌طور پیش‌فرض محدودیتی نداره.

## چک‌های موقع بالا اومدن

توی production برنامه قبل از گوش دادن تنظیماتش رو چک می‌کنه. با پیام `[config]` متوقف میشه اگه: `MONGODB_URI` نباشه، کلید LiveKit از نوع توسعه یا کوتاه باشه، یا تنظیمات S3 ناقص باشه. و هشدار میده اگه: `SMS_PROVIDER=console` باشه، `ADMIN_PHONES` خالی باشه، `SITE_URL` یا `LIVEKIT_PUBLIC_URL` تنظیم نشده باشه.
