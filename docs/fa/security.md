# امنیت و حریم خصوصی

برای گزارش آسیب‌پذیری به [SECURITY.md](../../SECURITY.md) سر بزن.

## چک‌لیست امنیتی برای کسی که سرور رو اجرا می‌کنه

قبل از اینکه کاربر واقعی دعوت کنی اینا رو انجام بده.

- [ ] **همه‌جا HTTPS.** برنامه توی production کوکی نشست رو `Secure` می‌ذاره، پس ورود روی HTTP ساده کار نمی‌کنه، و مرورگر هم بدون HTTPS میکروفون رو نمیده.
- [ ] **کلید و رمز جدید برای LiveKit** (`openssl rand -hex 24`)، یکسان توی `.env` و `livekit.yaml`. برنامه با جفت کلید توسعه بالا نمیاد.
- [ ] **`ADMIN_PHONES` فقط شماره‌هایی باشه که دست خودته.** اگه کسی سیم‌کارت یکی از این شماره‌ها رو تصاحب کنه، مدیر میشه. فهرست رو کوتاه نگه دار.
- [ ] **جلوی `/api/auth/*` رو توی پراکسی محدود کن.** تنظیم nginx آماده این کار رو می‌کنه؛ برای Caddy بلوک کامنت‌شده‌ی نمونه رو ببین. خود برنامه *هیچ* محدودیت تعداد درخواستی نداره؛ بدون اون، کسی می‌تونه یه شماره رو با پیامک بمباران کنه (هزینه برای تو) و کدهای ۵ رقمی رو حدس بزنه (۵ تلاش برای هر کد، و هر دقیقه یه کد جدید).
- [ ] **پورت‌های** `3000` (برنامه)، `7880` (API لایوکیت) و `27017` (MongoDB) **رو به اینترنت باز نذار.** برنامه رو روی `127.0.0.1` ببند (توی داکر کامپوز همین‌طوره) و MongoDB رو روی شبکه‌ی خصوصی یا localhost نگه دار.
- [ ] **MongoDB:** اگه چیزی غیر از برنامه بهش دسترسی داره، احراز هویت رو روشن کن و مشخصاتش رو توی `MONGODB_URI` بذار.
- [ ] **رمزها رو هیچ‌وقت کامیت نکن.** `.env*` و `livekit.yaml` توی گیت نادیده گرفته میشن. اگه رمزی یه بار کامیت یا جایی عمومی چسبانده شده، لو رفته حسابش کن: عوضش کن، فقط پاک کردن فایل کافی نیست.
- [ ] **باکت S3 خصوصی.** برنامه خودش فایل‌ها رو سرو می‌کنه و دسترسی‌ها رو چک می‌کنه؛ باکت عمومی این چک‌ها رو دور می‌زنه.
- [ ] **بکاپ‌ها** رمزنگاری شده و دور از سرور نگه‌داری بشن ([administration.md](administration.md#بکاپ)).
- [ ] **به‌روز نگه دار:** `npm audit`، سیستم‌عامل، ایمیج‌های داکر و نسخه‌های این پروژه.
- [ ] **توی production `SMS_PROVIDER=kavenegar`** (یا سرویس خودت) بذار. `console` فقط کد رو لاگ می‌کنه.

## برنامه خودش چی کار می‌کنه

- کد ورود و توکن نشست به‌صورت هش SHA-256 ذخیره میشن؛ نشست‌ها `httpOnly` و `SameSite=Lax` هستن و ۳۰ روز اعتبار دارن.
- تلاش اشتباه برای هر کد ۵ بار محدوده و ارسال دوباره برای هر شماره دقیقه‌ای یک بار.
- هر مسیر API اول نشست رو چک می‌کنه، بعد جایگاه کاربر توی سرور و کانال رو. کانال خصوصی از لیست‌ها، تاریخچه، رویدادهای زنده و «در حال تایپ» برای غیرعضوها پنهونه.
- آپلود: نوع عکس و صدا از روی بایت‌های فایل تشخیص داده میشه نه هدر کلاینت؛ اسم‌ها تمیز میشن؛ کلید ذخیره‌سازی رو سرور می‌سازه و خروج از پوشه (path traversal) رد میشه؛ حجم حداکثر ۵ مگابایته.
- webhookهای LiveKit با رمز مشترک تایید میشن.
- داده‌ی ساخت‌یافته‌ی صفحه‌های عمومی escape میشه تا تزریق اسکریپت نشه.
- کسی که از کانال حذف یا مسدود بشه، یا سرورش پاک بشه، از اتاق صوتی هم بیرون انداخته میشه.

## محدودیت‌های شناخته‌شده

با کاربرهات رک باش و اینا رو بهشون بگو.

- **رمزنگاری سرتاسری نداریم.** پیام‌ها توی MongoDB به‌صورت متن ساده ذخیره میشن. هر کسی به دیتابیس دسترسی داشته باشه، و مدیرهای سایت از طریق پنل مدیریت، می‌تونن بخوننشون. صدا و تصویر توی مسیر رمزنگاری میشن (DTLS-SRTP) ولی از سرور LiveKit تو رد میشن.
- **محدودیت تعداد درخواست توی خود برنامه نیست** (چک‌لیست رو ببین). اون رو توی پراکسی یا فایروال بذار.
- **هویت کاربر شماره‌ی موبایلشه.** شماره‌ها (برای ورود لازمن) ساده ذخیره میشن. به اعضای دیگه نشون داده نمیشن، ولی مدیرهای سایت می‌بینن.
- **فقط یه نمونه از برنامه** و بعضی حالت‌ها مثل حضور آنلاین توی حافظه‌ان ([architecture.md](architecture.md#چیزهایی-که-فقط-توی-حافظهان)).
- **کدهای ۵ رقمی کوتاه** فقط وقتی قابل قبولن که محدودیت درخواست هم داشته باشی.

## حریم خصوصی و چیزی که مدیر سرور می‌بینه

اگه یه نمونه‌ی عمومی اجرا می‌کنی، سیاستی منتشر کن که با کاری که واقعاً می‌کنی بخونه. صفحه‌های داخلی `/privacy` و `/terms` برای استقرار اصلی نوشته شدن (فارسی، سرورهای داخل ایران). قبل از راه‌اندازی نمونه‌ی خودت **حتماً بازبینی و ویرایششون کن** (`src/app/privacy/page.tsx` و `src/app/terms/page.tsx`). مثلاً می‌گن داده‌ها کجا نگه‌داری میشن و آیا مدیرها پیام‌ها رو می‌خونن.

اطلاعاتی که برنامه از هر آدم نگه می‌داره: شماره‌ی موبایل، اسم، رنگ، بیو، وضعیت، عکس نمایه، پیام‌ها و فایل‌هایی که فرستاده، عضویت‌ها، دوست‌ها و زمان آخرین بازدید. تماس‌ها و اشتراک صفحه توسط برنامه ضبط نمیشن (ضبط LiveKit تنظیم نشده).

برای پاک کردن اطلاعات یه نفر، کاربر رو از پنل مدیریت حذف کن و بعدش مطمئن شو بکاپ‌ها طبق سیاستت قدیمی و حذف میشن.

## می‌خوای فورکت رو متن‌باز کنی؟ قبل از push چک کن

```bash
git grep -nIE "api[_-]?key|secret|password|token" -- . ':!package-lock.json' | less
git log -p --all -S"<مقداری که به‌عنوان رمز استفاده کردی>" | head
```

گشتن توی تاریخچه مهمه: پاک کردن فایل، اون رو از کامیت‌های قبلی در نمیاره. اگه رمز واقعی توی تاریخچه هست، اول عوضش کن و بعد تاریخچه رو بازنویسی کن (مثلاً با `git filter-repo`)، و بعد منتشر کن.
