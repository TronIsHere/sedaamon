# معماری

## نمای کلی

```
browser ──https──▶ reverse proxy ──▶ server.ts (Next.js 16 + Socket.io) ──▶ MongoDB
   │                    │                       ▲                      └──▶ uploads: disk or S3
   │                    └─wss─▶ LiveKit ────────┘ webhooks (who joined / left)
   └── UDP 50000-60000 / TCP 7881 / TURN 443/udp, 5349 ──▶ LiveKit (media)
```

برنامه فقط یه پردازش Node داره (`server.ts`) که هم صفحه‌ها و API رو با Next.js سرو می‌کنه و هم کانال زنده رو با Socket.io. صدا و تصویر هیچ‌وقت از این پردازش رد نمیشن: مرورگر از برنامه یه توکن کوتاه‌مدت می‌گیره و بعد مستقیم با LiveKit حرف می‌زنه.

## بخش‌ها

| بخش | کجاست | چی کار می‌کنه |
|---|---|---|
| سرور سفارشی | `server.ts` | Next.js و Socket.io رو روی یه سرور HTTP بالا میاره؛ سوکت‌ها رو با کوکی نشست احراز هویت می‌کنه؛ «در حال تایپ» رو پخش می‌کنه؛ زمان‌بند رویدادها و پاک‌کننده‌ی آپلودها رو اجرا می‌کنه؛ تنظیمات production رو چک می‌کنه. |
| مسیرهای API | `src/app/api/**/route.ts` | endpointهای JSON. هر کدوم کوتاهه و کار رو به `src/server/*` میسپره. |
| منطق سرور | `src/server/*` | قواعد برنامه: `permissions` و `access` (کی چی رو ببینه و انجام بده)، `messages`، `channels`، `servers`، `roles`، `bans`، `friends`، `dms`، `events`، `files`، `notifications`، `reads` (علامت خوانده‌شدن). |
| مدل‌های داده | `src/server/models.ts` | طرح‌واره‌های Mongoose. |
| زنده | `src/server/realtime.ts`، `presence.ts` | اتاق‌های سوکت (`user:<id>` و `server:<id>`)، حضور آنلاین، نقشه‌ی شرکت‌کننده‌های صوتی توی حافظه. |
| احراز هویت | `src/app/api/auth/*`، `session.ts`، `sms.ts` | شماره‌ی موبایل و کد یک‌بارمصرف ← کوکی نشست. |
| صدا | `src/server/livekit.ts`، `src/app/api/livekit/*` | برای کانال‌هایی که کاربر اجازه داره توکن LiveKit میده؛ webhookها رو می‌گیره تا معلوم باشه کی توی کانال صوتیه. |
| ذخیره‌سازی | `src/server/storage.ts` | یه رابط، دو پشتیبان: دیسک محلی یا S3 سازگار. |
| رابط کاربری | `src/components/*` | برنامه‌ی React 19 (`app/`)، پنل مدیریت، صفحه‌های معرفی و اطلاعات، خوش‌آمدگویی. |
| کد مشترک | `src/lib/*` | نوع‌ها، تقویم شمسی، نرمال‌سازی شماره، جستجو، منشن، قواعد اعلان؛ هم مرورگر استفاده می‌کنه هم سرور، و تست واحد داره. |
| پوسته‌ی دسکتاپ | `desktop/` | برنامه‌ی Tauri که برنامه‌ی وب رو توی پنجره میاره (تری، نشان، اعلان بومی، لینک عمیق). |

## داده

همه‌چیز به‌جز فایل‌های آپلودی توی MongoDB هست: کاربر، نشست، کد یک‌بارمصرف، سرور، عضو، نقش، دسته، کانال، پیام، گفتگوی خصوصی، دوستی، اعلان، رویداد و اطلاعات آپلودها. عکس نمایه و آیکون سرور هم به‌صورت سند توی MongoDB ذخیره میشن (نه توی فضای آپلود).

داده‌هایی که انقضا دارن (نشست، کد یک‌بارمصرف، اعلان بعد از دو هفته، رویداد یک هفته بعد از شروع) با ایندکس TTL مانگو خودشون پاک میشن.

## مسیر یک درخواست

۱. **ورود:** `POST /api/auth/otp` هش کد رو ذخیره می‌کنه و پیامک می‌فرسته؛ `POST /api/auth/verify` کد رو چک می‌کنه، اگه لازم بود کاربر می‌سازه و کوکی `sid` رو میذاره (httpOnly و توی production با `Secure`). فقط هش SHA-256 توکن نشست ذخیره میشه.
۲. **خوندن و نوشتن:** مسیرهای API کوکی رو می‌خونن، کاربر رو لود می‌کنن، دسترسی به سرور و کانال مقصد رو چک می‌کنن و بعد کار رو انجام میدن.
۳. **زنده:** بعد از هر نوشتن، سرور رویداد Socket.io رو برای کسایی می‌فرسته که اجازه‌ی دیدنش رو دارن (اتاق سرور، یا مخاطبین کانال برای کانال خصوصی، یا دو طرف پیام خصوصی).
۴. **ورود به کانال صوتی:** کلاینت از `POST /api/livekit/token` برای یه کانال توکن می‌خواد. سرور دسترسی رو چک می‌کنه و یه توکن LiveKit با اعتبار ۶ ساعت برای اتاق `ch_<channelId>` میده. LiveKit موقع ورود و خروج `POST /api/livekit/webhook` رو صدا می‌زنه (با بررسی امضا) و سرور فهرست شرکت‌کننده‌ها رو پخش می‌کنه.
۵. **فایل‌ها:** از طریق API آپلود میشن (نوع فایل از روی بایت‌ها تشخیص داده میشه نه هدر)، با یه کلید ساخته‌شده توسط سرور ذخیره میشن، و از طریق API دانلود میشن که هر بار دسترسی کانال رو چک می‌کنه.

## چیزهایی که فقط توی حافظه‌ان

حضور آنلاین و نقشه‌ی شرکت‌کننده‌های صوتی توی پردازش Node نگه‌داری میشه. با ری‌استارت، حضور پاک میشه (سوکت‌ها دوباره وصل میشن) و نقشه‌ی صوتی موقع بالا اومدن از LiveKit دوباره ساخته میشه. به همین دلیل **فقط یه نمونه از برنامه اجرا کن**؛ برای چند نمونه باید آداپتور مشترک برای Socket.io و حضور اضافه بشه که هنوز ساخته نشده.

## فناوری‌ها

Next.js 16 (App Router، سرور سفارشی)، React 19، TypeScript، Tailwind CSS 4، Socket.io، Mongoose 9 و MongoDB، LiveKit (SDK سرور و کلاینت)، AWS S3 SDK، sharp (پردازش تصویر)، Zod، Vitest و Tauri 2 (دسکتاپ).

> این پروژه از یه نسخه‌ی جدید Next.js استفاده می‌کنه که API هاش با نسخه‌های قدیمی فرق داره. قبل از تغییر کدهای سطح فریم‌ورک، راهنماهای `node_modules/next/dist/docs/` رو بخون.

## طراحی برای کار بدون اینترنت بین‌الملل

فونت (وزیرمتن) از `node_modules` سرو میشه، آیکون‌ها داخل پروژه‌ان و LiveKit با `use_external_ip: false` تنظیم شده تا هیچ‌وقت از سرور STUN عمومی سوال نکنه. مرورگر هیچ چیزی از میزبان‌های بیرونی لازم نداره، و همین باعث میشه برنامه روی شبکه‌ی ملی هم کار کنه.
