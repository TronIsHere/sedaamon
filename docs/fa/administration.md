# مدیریت و نگهداری

## پنل مدیریت

وقتی با شماره‌ای وارد شدی که توی `ADMIN_PHONES` هست، برو به `/admin`. اگه این متغیر خالی باشه، پنل برای همه خاموشه.

| تب | چی کار می‌تونی بکنی |
|---|---|
| نمای کلی | تعداد کاربر، کاربر جدید این هفته، سرور، سرور عمومی، کانال، پیام، آنلاین‌ها و کسایی که توی کانال صوتی‌ان |
| کاربران | جستجو با اسم یا شماره، ویرایش اسم و بیو، خروج از همه‌ی دستگاه‌ها، حذف حساب (به‌جز حساب مدیرها) |
| سرورها | جستجو، تغییر اسم، ساخت لینک دعوت جدید، برداشتن از فهرست عمومی، حذف |
| کانال‌ها | دیدن کانال‌های یه سرور، تغییر اسم یا حذف کانال |
| پیام‌ها | دیدن و حذف پیام‌های یه کانال (برای مدیریت محتوا و گزارش سوءاستفاده) |

تغییرها همون لحظه اعمال میشن و کسایی که تحت تاثیرن زنده به‌روز میشن یا از کانال صوتی بیرون میرن.

مدیرها از طریق این پنل می‌تونن پیام‌های کانال‌های عمومی و خصوصی رو بخونن. این رو حتماً توی سیاست حریم خصوصی‌ات بنویس ([security.md](security.md#حریم-خصوصی-و-چیزی-که-مدیر-سرور-میبینه)).

## نقش‌ها داخل یه سرور

| نقش | چی کار می‌تونه بکنه |
|---|---|
| مالک | همه‌چیز توی اون سرور؛ تنها کسیه که مدیر تعیین می‌کنه و سرور رو حذف می‌کنه |
| مدیر | کانال و دسته می‌سازه و مدیریت می‌کنه، پیام پاک می‌کنه، اعضای پایین‌تر از خودش رو بی‌صدا، اخراج یا مسدود می‌کنه |
| نقش دلخواه | مالک و مدیرها می‌سازن تا کانال خصوصی رو محدود کنن یا اعضا رو دسته‌بندی کنن |
| عضو | هر جا اجازه داشته باشه می‌خونه و می‌نویسه |

## بکاپ

چی رو بکاپ بگیر:

| چی | کجاست | چطور |
|---|---|---|
| دیتابیس | MongoDB | `mongodump` |
| فایل‌های آپلودی | ولوم `uploads` یا `UPLOAD_DIR`، یا باکت S3 | کپی پوشه، یا نسخه‌گذاری و همتاسازی خود باکت |
| تنظیمات | `.env` یا `.env.production` و `livekit.yaml` | یه کپی جای امن نگه دار؛ چون رمز دارن، رمزنگاریشون کن |

با داکر کامپوز:

```bash
# دیتابیس
docker compose exec -T mongo mongodump --archive --gzip --db sedaamon > sedaamon-$(date +%F).archive.gz
# آپلودها
docker run --rm -v sedaamon_uploads:/data -v "$PWD":/backup alpine tar czf /backup/uploads-$(date +%F).tgz -C /data .
```

(اسم ولوم با اسم پوشه‌ی پروژه شروع میشه؛ با `docker volume ls` چک کن.)

بازیابی:

```bash
docker compose exec -T mongo mongorestore --archive --gzip --drop < sedaamon-2026-01-01.archive.gz
```

بدون داکر: `mongodump --db sedaamon --out backup/` و `mongorestore --drop backup/`.

حداقل یه بار بازیابی رو روی یه ماشین جدا امتحان کن.

## به‌روزرسانی

۱. بکاپ بگیر (بالا).
۲. یادداشت‌های نسخه رو بخون که ببینی تغییر ناسازگاری هست یا نه.
۳. آپدیت کن و دوباره build کن:

```bash
git pull
# داکر
docker compose up -d --build
# PM2
npm ci && npm run build && pm2 restart all
```

تغییرهای دیتابیس که داده‌ی قدیمی لازم داره (مثلاً مهاجرت نقش‌ها) موقع بالا اومدن خودکار انجام میشه.

## لاگ و سلامت

- داکر: `docker compose logs -f app`. PM2: `pm2 logs sedaamon-web`.
- دنبال خط‌هایی بگرد که با `[config]` (تنظیمات)، `[livekit]` و `[otp]` شروع میشن.
- کانتینر سلامتش رو با درخواست به `/` گزارش میده؛ `docker compose ps` نشونش میده.
- لاگ رو بدون بررسی جایی عمومی نذار: با `SMS_PROVIDER=console` کد ورود توش هست.

## عوض کردن پیامک، ذخیره‌سازی یا دامنه

- **پیامک:** `SMS_PROVIDER` و کلیدهای سرویس رو عوض کن و ری‌استارت بزن.
- **جابه‌جایی فایل بین دیسک و S3:** برنامه فایل‌ها رو خودش منتقل نمی‌کنه. قبل از عوض کردن، فایل‌های قبلی رو با همون کلیدها توی مخزن جدید کپی کن، وگرنه پیوست‌های قدیمی گم‌شده نشون داده میشن.
- **دامنه‌ی جدید:** `SITE_URL`، `LIVEKIT_PUBLIC_URL`، پراکسی و گواهی‌ها رو عوض کن و دوباره build بزن (آدرس عمومی داخل صفحه‌ها ساخته میشه). نشست‌ها کوکی هر دامنه‌ان، پس همه باید دوباره وارد بشن.
