# رفع اشکال

## برنامه بالا نمیاد: "Refusing to start"

خط‌های `[config]` بالای خطا رو بخون. دلیل‌های رایج: کلید LiveKit هنوز `devkey` هست، رمز کمتر از ۳۲ کاراکتره، `MONGODB_URI` نیست، یا `S3_ENDPOINT` رو گذاشتی ولی باکت و کلیدها نیستن. `.env` رو درست کن و دوباره بالا بیار. جزئیات: [configuration.md](configuration.md#چکهای-موقع-بالا-اومدن).

## نمی‌تونم وارد بشم

- **پیامک نمیاد.** `SMS_PROVIDER=kavenegar`، کلید API رو چک کن و اینکه قالب وجود داره و دقیقاً یه `%token` داره. خطای سرویس توی لاگ سرور هست. با `SMS_PROVIDER=console` کد فقط توی لاگه.
- **«کد منقضی شده» یا «تعداد تلاش‌ها زیاد بود».** کد ۲ دقیقه اعتبار داره و ۵ بار اشتباه مجازه. کد جدید بگیر (بین دو درخواست ۶۰ ثانیه صبر کن).
- **ورود انجام میشه ولی بلافاصله خارج میشی.** کوکی توی production `Secure` هست: باید با `https://` باز کنی. چک کن پراکسی هدر `X-Forwarded-Proto` رو می‌فرسته و آدرس `http` و `https` رو قاطی نمی‌کنی.
- **خطای ۴۲۹ موقع ورود.** محدودیت درخواست پراکسی ([`deploy/nginx.conf`](../../deploy/nginx.conf)) داره کار می‌کنه. یه دقیقه صبر کن.

## `/admin` باز نمیشه

شماره‌ات باید توی `ADMIN_PHONES` باشه (هر شکلی: `0912…` یا `+98912…`) و بعد از تغییرش برنامه ری‌استارت شده باشه. اگه متغیر خالیه، پنل خاموشه.

## صدا وصل نمیشه

۱. **HTTPS داری؟** میکروفون روی HTTP ساده بسته‌ست.
۲. **`LIVEKIT_PUBLIC_URL`** باید `wss://rtc.example.com` باشه (نه `ws://` و نه `localhost`). سایت `rtc.` توی پراکسی باید ارتقای WebSocket رو به پورت `7880` برسونه.
۳. **`node_ip`** توی `livekit.yaml` باید آی‌پی *عمومی* سرور باشه.
۴. **فایروال:** `50000-60000/udp` و `7881/tcp` باز باشن. اگه کاربرهای شبکه‌ی موبایلی وصل نمیشن ولی وای‌فای اوکیه، بلوک `turn:` رو فعال کن، `443/udp` و `5349/tcp` رو باز کن و برای TURN گواهی بذار.
۵. **کلیدها:** کلید و رمز `.env` باید با `keys:` توی `livekit.yaml` یکی باشه. اگه نباشه، توی لاگ LiveKit «invalid token» می‌بینی و فهرست شرکت‌کننده‌ها هیچ‌وقت به‌روز نمیشه (چون امضای webhook رد میشه).
۶. **LiveKit بالاست؟** `docker compose logs livekit` یا `pm2 logs sedaamon-livekit`. از روی همون سرور `curl http://127.0.0.1:7880` باید `OK` بده.
۷. **داکر روی مک یا ویندوز:** شبکه‌ی host برای LiveKit توی داکر دسکتاپ کار نمی‌کنه. روی یه ماشین لینوکس تست کن.

## صدا وصل میشه ولی چیزی نمی‌شنوم (آیفون و سافاری)

سافاری صدا رو فقط بعد از یه تاچ شروع می‌کنه. با تاچ روی کانال وارد شو؛ اگه نواری خواست یه بار دیگه بزنی، بزن. مرورگرهای داخل اپ (تلگرام، اینستاگرام) معمولاً WebRTC ندارن؛ لینک رو توی سافاری یا کروم باز کن.

## «چه کسی توی کانال صوتیه» غلط یا خالیه

این فهرست از webhookهای LiveKit میاد. چک کن `webhook.urls` توی `livekit.yaml` به آدرس برنامه *از دید LiveKit* اشاره کنه (وقتی LiveKit روی شبکه‌ی host هست، `http://127.0.0.1:3000/api/livekit/webhook`) و کلیدها یکی باشن.

## فایل‌های آپلودی گم‌شده نشون داده میشن

- دیسک محلی: پوشه باید بعد از ری‌استارت بمونه (ولوم `uploads` توی داکر) و کاربر برنامه اجازه‌ی نوشتن توش داشته باشه.
- S3: آدرس، باکت، کلیدها و `S3_FORCE_PATH_STYLE` رو چک کن. بعد از عوض کردن مخزن، فایل‌های قدیمی توی مخزن قبلی می‌مونن.
- فایل بزرگ‌تر از ۵ مگابایت رد میشه. پشت nginx مقدار `client_max_body_size` باید حداقل `10m` باشه (توی نمونه هست).

## قابلیت‌های زنده (پیام، در حال تایپ) به‌روز نمیشن

پراکسی باید ارتقای WebSocket (هدرهای `Upgrade` و `Connection`) رو رد کنه و زمان خوندن طولانی داشته باشه. نمونه‌ها دارن. توی کنسول مرورگر دنبال درخواست‌های ناموفق `/socket.io/` بگرد.

## توسعه

- **گوشی به سرور توسعه وصل نمیشه:** آدرسش رو توی `DEV_ALLOWED_ORIGINS` بذار و `http://<آی‌پی تو>:3000` رو باز کن. گوشی می‌تونه گوش بده، ولی مرورگر روی HTTP ساده میکروفون نمیده.
- **تست‌های دیتابیس رد میشن (skipped):** `TEST_MONGODB_URI` رو به یه دیتابیس آزمایشی بده.
- **پورت اشغاله:** `PORT` رو عوض کن؛ اگه عوض کردی `webhook.urls` توی `livekit.dev.yaml` رو هم درست کن (الان به پورت `3100` اشاره می‌کنه).

هنوز گیری؟ یه issue باز کن و بنویس چی کار کردی، انتظارت چی بود، خط‌های مربوط لاگ (رمز، شماره و کد ورود رو پاک کن) و محیطت (داکر یا PM2، سیستم‌عامل، مرورگر).
